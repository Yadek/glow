# Glow 1.3.0 validation

Development verification: 17 October 2026. This is a candidate build; no release tag or published binary release was created.

## Confirmed

- Release build of Glow.sln: 0 warnings, 0 errors.
- Self-contained win-x64 single-file publication, product version 1.3.0.
- C# runner: 132 assertions. Real bitmap fixtures cover device matching, negative desktop coordinates, Tile/Span rendering, image fallback, file release, independent bitmap ownership, cancellation across delayed close/reopen, keyboard slider policy, high-contrast pill text and layout at 100/150/200%.
- Wallpaper Engine command timeout and oversized output are tested against a child fixture executable. This does not establish compatibility with a running Wallpaper Engine installation.
- Python collector: 10 unittest cases covering releases/assets pagination, daily replacement, unavailable traffic, preservation on fetch failure, corrupt history, a one-point chart and gaps.
- Read-only Windows smoke outside the restricted environment: both attached logical monitors produced Windows wallpaper previews with device identities. No brightness or gamma writes were performed.
- DWM accepted the backdrop request. This confirms API success, not the visual quality of Acrylic.
- Public GitHub API collection succeeded: the actual snapshot at 2026-10-16T21:05:00Z contained 94 release asset downloads, 3 stars and 0 forks. Traffic was unavailable and stayed absent. These are development observations, not fabricated historical series.
- Independent whole-change review found three Important issues (Tile origin, shared-menu night state, high-contrast text); all were fixed and the full suite passed. Delayed lifecycle coverage was also added.

## Pending runtime checks

- Visual Acrylic on the user's desktop, light theme and actual high-contrast Windows theme. Fixture rendering does not prove DWM composition.
- A running Wallpaper Engine installation. Multi-monitor Engine location mapping is disabled; Windows wallpaper or a placeholder is used instead. Single-display support is a static project preview, never a live stream.
- Actual DDC/CI adjustment, gamma changes, sleep/resume and monitor hot-plug. Existing hardware-control code remains in place; no new hardware compatibility claims are made.
- Hosted GitHub Actions execution. The statistics workflow intentionally runs on the default branch; its initial history branch/README graph are created after the change reaches that branch and a collection succeeds. The optional GH_TRAFFIC_TOKEN secret must be configured separately through GitHub UI.

## Decisions during implementation

- The fresh task-owned clone and feature branch provide isolation; the user's existing checkout was not modified.
- PowerShell was used for the execution ledger because the bundled bookkeeping scripts require an unavailable bash shell.
- The test runner is self-contained because this machine has .NET 10 shared runtimes while the product targets .NET 8. No test framework or product UI dependency was added.
- Wallpaper Engine multi-display mapping could not be verified, so index guessing was rejected. The cost is Windows-only fallback for those configurations until a verified mapping is available.
- Local NuGet restore used cached framework packs with `-p:NuGetAudit=false` after the sandbox blocked network access; CI/product audit configuration was not changed. The sandbox's compiler named-pipe startup also required local `-m:1 -p:UseSharedCompilation=false`.
- Hardware and unverified runtime cases remain explicitly pending rather than being inferred from a green build. They must be checked before publishing a stable release.

GitHub access was verified as Yadek, with push rights to Yadek/glow. Product commits use the repository owner's existing noreply identity and contain no AI co-author trailers. Historical commits were not rewritten.
